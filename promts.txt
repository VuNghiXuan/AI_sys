# BẢN CHỈ DẪN HỆ THỐNG: KIẾN TRÚC TẬP ĐOÀN AI TỰ TRỊ (VNXBOX ENTERPRISE - ULTIMATE SPEC 2026)

## 📌 I. TẦM NHÌN SẢN PHẨM & QUY CHUẨN KỸ THUẬT CỐT LÕI

1. **Kiến trúc Local-First & Headless:**
   - **Bảo mật tuyệt đối:** Hoạt động 100% Offline trong mạng LAN nội bộ (Ollama + `qwen2.5-coder:7b` cho code/toán, `llama3`/`gemma2` cho tổng hợp, `bge-m3` cho Vector Embeddings).
   - **Phân tách hoàn toàn:** Backend Core (Django REST API / Daphne ASGI WebSocket) và Frontend Engine (Alpine.js + Tailwind CSS).

2. **Triệt tiêu Ảo giác Tính toán (Zero-Hallucination Math):**
   - **Cấm AI tự nhẩm số học hay hardcode logic:** Mọi công thức tài chính, kế toán, giá vốn, định mức hay tỷ lệ chiết khấu phải được viết thành script Python và thực thi trong **Restricted Sandbox Environment** (`knowledge/sandbox.py`: Timeout 2–3s, RAM 128MB, chặn các thư viện độc hại `os`, `sys`, `subprocess`, `socket`, `requests`).
   - Tích hợp **Neuro-Symbolic Solver (Z3 Theorem Prover / SymPy)** để đạt độ chính xác 100% về mặt toán học.

3. **Quy chuẩn Lập trình Vibercode, Giới hạn File (< 300 dòng) & Bắt buộc Logging:**
   - **Giới hạn tuyệt đối < 300 dòng/file:** Mọi file mã nguồn Python, JS, HTML hoặc config do AI sinh ra KHÔNG ĐƯỢC PHÉP vượt quá 300 dòng.
   - **Cơ chế Tự động Tách file (File Splitting & Modularization):** Khi một module có xu hướng phình to vượt 300 dòng, AI bắt buộc tách thành các file con chuyên biệt (VD: `base.py`, `memory_loader.py`, `chat_handler.py`) hoặc đưa vào thư mục chuyên môn (`consumers/`, `services/`, `utils/`, `views/`) kèm file điều hướng sạch bên ngoài. Không nhét logic vào `__init__.py`.
   - **Chú thích vị trí bắt buộc:** Dòng đầu tiên của mọi file mã nguồn xuất bản phải ghi rõ đường dẫn và tên file đầy đủ.
   - **Nguyên tắc Nguyên tử (Full File Output):** Khi sinh mã nguồn mới hoặc tạo bản vá, AI phải xuất **toàn bộ mã nguồn hoàn chỉnh của file**, không dùng dấu ngoặc nhọn hoặc chú thích dạng `// ... giữ nguyên code cũ ...`.
   - **Quy chuẩn Logging Bắt buộc (Mandatory Logging Policy):**
     - Cấm tuyệt đối dùng `print()` thô sơ trong production code. Mọi service backend, ASGI consumer, và executor bắt buộc phải sử dụng module `logging` chuẩn của Python (`logger = logging.getLogger(__name__)`).
     - **Chiến lược 3 tầng:** Terminal (Console level INFO/DEBUG), File Log tập trung (`logs/vnxbox_system.log` với FileHandler encoding UTF-8 và cơ chế rotation), và Database/WebSocket Broadcast (lưu vết sự kiện quan trọng lên War Room).
     - **Bẫy lỗi ngoại lệ (Try-Catch & Exc_Info):** Mọi hàm quan trọng gọi LLM Ollama, xử lý database hoặc thao tác DAG task bắt buộc phải bọc trong `try...except` kèm `exc_info=True`.

4. **Minh bạch Trích dẫn & Định vị Sâu (Deep Traceability):**
   - Trích dẫn định vị đa tầng: `[Doanh Nghiệp / Phân Hệ] > [Domain Lĩnh Vực] > [Sub-Domain Nghiệp Vụ] > [Chương X] > [Điều Y] > [Mục Z / Sheet Name]`.
   - Tích hợp **1-Click Edit** mở thẳng Admin Dashboard và lưu trữ lịch sử phiên bản (`KnowledgeHistory`) hỗ trợ so sánh Diff và Rollback 1-Click.

5. **Bản đồ Dự án & Tri thức (Project Mapping & Graph Anchoring):**
   - Quản lý cấu trúc dự án (`ProjectNode`, `AgentTaskDAG`, `PROJECT_MAP.md`) trực tiếp qua Django ORM và AST Scanner để kiểm soát độ dài, chống trùng lặp hàm/class và đồng bộ đồ thị tri thức doanh nghiệp bằng Neo4j.

## ⚡ II. KIẾN TRÚC XỬ LÝ PROMPT DÀI & TỐI ƯU PHẦN CỨNG LOCAL (CPU-ONLY)

### 1. Tối ưu Phần cứng Đa nhân (Core Pinning & Token Budget)
- **Phân chia nhân xử lý (Core Pinning):** Trên CPU kiến trúc lai (P-cores + E-cores như Intel Core i7-14700, 32GB RAM), cấu hình biến môi trường hệ thống để tránh dàn trải sang E-cores và giữ model trực tuyến trên RAM:
  - `OLLAMA_NUM_THREAD=10` (ép sử dụng đúng cụm nhân hiệu năng cao P-cores).
  - `OLLAMA_KEEP_ALIVE=-1` (giữ model `qwen2.5-coder:7b` thường trực trên RAM, loại bỏ độ trễ nạp từ ổ đĩa).
- **Kiểm soát ngân sách Token (Token Budget):** Giữ tổng độ dài mỗi lần gọi Ollama (System Prompt + User Prompt) dưới **1.500 - 2.000 tokens** (~4.000 - 5.000 ký tự) để pha đọc đầu vào (Prompt Evaluation) không bị nghẽn cổ chai trên CPU, đảm bảo thời gian phản hồi nằm gọn trong 15 - 45 giây.

### 2. Kiến trúc Lai Phân cấp (Python Hierarchical Chunker + Map-Reduce + JIT Context)
Khi tiếp nhận bản chỉ đạo hoặc Spec siêu dài (> 250 ký tự bật cờ bảo vệ `IS_COMPLEX_SPEC = True`, > 1.500 ký tự kích hoạt băm nhỏ):
1. **Long-Prompt Safeguard (Chặn nhận nhầm Intent):** Tuyệt đối chặn không cho các yêu cầu dài rơi vào nhóm xã giao/họp ngắn (`SMALL_TALK`, `MEETING_CALL`), ép chuyển thẳng sang luồng điều phối `DEEP_CODE`.
2. **Bước 1 - Cắt nhỏ phân cấp bằng Python (0 giây):** Dùng Regex tách văn bản theo cấu trúc tiêu đề Markdown (`## Mục lớn` -> `### Mục nhỏ`), lưu nguyên bản gốc vào bảng tạm trong Django DB (`WorkingMemory` / `SpecDocument`) để bảo toàn dữ liệu.
3. **Bước 2 - Nén ngữ cảnh Map-Reduce:** Chia Spec thành các gói nhỏ (~1.500 ký tự/gói), gọi Ollama tóm tắt từng gói theo cấu trúc JSON (`muc_lon`, `yeu_cau_cot_loi`, `file_lien_quan`) và cập nhật tiến trình từng phần lên Live Trace Console.
4. **Bước 3 - Just-in-Time (JIT) Context Injection:** Khi thực thi từng task qua LangGraph & Neo4j, chỉ bơm đúng 3 mảnh ghép tối thiểu: `[Tóm tắt mục tiêu tổng thể ~200 từ] + [Chi tiết Task hiện tại] + [Mã nguồn liên quan từ Neo4j]`.

### 3. Cơ chế Ký ức Ngữ cảnh Đa tầng (Context Hydration & Memory)
- **Tầng A (Database Context Rehydration):** Khi bắt đầu phiên mới, hệ thống tự động query lại lịch sử `AgentDiscussion` và các mốc quyết định (`IntentMemory`, `AgentTaskDAG`) từ các phiên trước, nén thành tóm tắt nhúng vào System Prompt để AI không bị mất trí nhớ ngắn hạn.
- **Tầng B (Semantic Memory Retrieval):** Khi người dùng nhắc lại chủ đề cũ, Intent Router kết hợp Vector/BM25 quét lịch sử để phục hồi đúng ngữ cảnh liên quan.

## 🧠 III. HỆ THỐNG INTENT ROUTER ĐA TẦNG & TỰ HỌC (3-TIER INTENT ROUTING)

1. **Lớp 1: Fast Chit-Chat & System Status (0 giây - Không gọi Ollama):** Dùng từ khóa/Regex cho câu ngắn chào hỏi, điểm danh họp (`SMALL_TALK`, `MEETING_CALL`) để BOD CEO phản hồi ngay lập tức.
2. **Lớp 2: Direct Database / State Query (Tốc độ mili-giây):** Truy vấn trực tiếp Django DB (`AgentRegistry`, `AgentTaskDAG`) báo cáo nhân sự, tiến độ công việc.
3. **Lớp 3: Deep Business & Vibercode Reasoning:** Kích hoạt chuỗi DAG qua LangGraph + Neo4j + Ollama (`qwen2.5-coder`).
4. **Cơ chế Tự học Động (`IntentMemory`):** Lưu vết câu hỏi kèm nhãn ý định, dùng Embedding local so sánh độ tương đồng (> 85%) và cập nhật tức thì qua Human-in-the-Loop Feedback (`LIKE` / `CORRECT`).

  - *Rất cao (Bảo mật Core, Deploy):* Duyệt thủ công + Xác thực tác động.
